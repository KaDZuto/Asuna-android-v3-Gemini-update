## 2026-10-04 — Шаг 4: мост Antigravity + сервер Silero TTS (Claude, без сборки)

### Что сделано
1. **`server/antigravity_bridge.py` усилен** (статически, без запуска против живого `agy`):
   - `subprocess.run(..., stdin=subprocess.DEVNULL, capture_output=True, timeout=print_timeout + 30)` — закрывает stdin, чтобы `agy -p` не висел в pipe-режиме.
   - Добавлен флаг `--print-timeout` (передаётся в `agy --print-timeout`, по умолчанию 120 с).
   - Откат через transcript: при пустом `stdout` читается самый свежий файл каталога transcript (env `AGY_TRANSCRIPT_DIR` или стандартные пути `~/.antigravity/transcripts` и т.п., свежесть ≤ 10 минут); иначе 502 с понятной ошибкой.
   - Хост по умолчанию изменён на `127.0.0.1` (было `0.0.0.0`); `--host 0.0.0.0` остаётся осознанным выбором.
   - Опциональный токен авторизации: `--token` / env `BRIDGE_TOKEN`, заголовок `Authorization: Bearer <token>` (принимается и голый токен), 401 при несоответствии.
   - Лимит тела запроса 64 КБ (413), проверка `Content-Length` и непустого `messages`.
   - Валидация поля `model`: белый список + регекс `^[a-zA-Z0-9][a-zA-Z0-9._-]{0,63}$` (400).
   - CORS: заголовок `Access-Control-Allow-Origin` задаётся через `--cors-origin` (по умолчанию `*`, но с токеном рекомендуется конкретизировать).
   - `HTTPServer` заменён на `ThreadingHTTPServer`.
2. **Создан `server/tts_server.py`**: `ThreadingHTTPServer`, `GET /?text=...&speaker=baya` → WAV (mono int16, 48 kHz), `GET /health` → 200/503, белый список спикеров (`baya`, `aidar`, `kseniya`, `xenia`, `eugene`), лимит текста 3000 символов. При отсутствии `torch`/silero — понятная 503-ошибка вместо падения. Приложение всё равно делает авто-откат на системный TTS.
3. **README.md**: добавлены инструкции запуска `server/tts_server.py` и обновлён пример запуска моста с `--token`.

### Проверено
- `python3 -m py_compile` обоих файлов — синтаксис в порядке.
- Логика токена/лимитов/валидации не прогонялась end-to-end (нет живого `agy` и без torch-окружения в моей среде).

## Шаг 3 — Безопасность и конфиг (2026-10-04, без сборки)

Что сделано:

1. **`AvatarWebView.kt` — WebView закрыт.**
   - Убраны `allowUniversalAccessFromFileURLs = true` и `allowFileAccessFromFileURLs = true` (теперь `false`).
   - `allowFileAccess` теперь `false` (контент грузится через `WebViewAssetLoader`, прямой доступ к `file://` не нужен).
   - `mixedContentMode` изменён с `MIXED_CONTENT_ALWAYS_ALLOW` на `MIXED_CONTENT_NEVER_ALLOW`.
   - `WebView.setWebContentsDebuggingEnabled(true)` теперь работает только при `FLAG_DEBUGGABLE` (т.е. в debug-сборке), в release — выключено.
   - `onPermissionRequest`: права выдаются только если `request.origin` начинается с `https://appassets.androidplatform.net`, иначе `request.deny()`.
   - Добавлен `shouldOverrideUrlLoading`: навигация разрешена только на host `appassets.androidplatform.net`, всё остальное блокируется (возвращаем `true` = перехватываем).
   - `onCreateWindow` больше не создаёт новый WebView с `allowFileAccess = true`; просто блокируем (`return false`), логируем. Также `setSupportMultipleWindows(false)`, `javaScriptCanOpenWindowsAutomatically = false`.

2. **`AndroidManifest.xml`.**
   - `android:allowBackup="true"` → `"false"` — API-ключи/память/календарь больше не уходят в облачный бэкап (правила `backup_rules`/`data_extraction_rules` при этом больше не применяются — это осознанно безопаснее; при необходимости потом вернуть через xml-правила).
   - Добавлен блок `<queries>` с intent-action `android.intent.action.TTS_SERVICE` — на Android 11+ TTS-движки будут видны (проблема особенно у Xiaomi).
   - `AsunaCompanionService` оставлен как есть: foreground-тип `microphone`, `startForeground` не вызывается и нигде не запускается. **Не ломаем сейчас, но отмечаем:** если когда-либо запустят через `startForegroundService` без `startForeground()` — краш через ~5 секунд. Оставлено для исправления позже.

3. **`app/build.gradle.kts` — удалена мёртвая задача `copyAvatarAssets`** (строки 21–90): пути `C:\Users\Alexius\...` и `../hermes_paperclip_agent`, запись в `avatar/models`. Ссылка `tasks.named("preBuild") { dependsOn(copyAvatarAssets) }` тоже удалена. Ассеты закоммичены, задача не нужна. Компиляцию не проверял — но удалены только блок задачи и её регистрация в preBuild, на остальное не влияет.

4. **Удалён дубликат моделей:** `app/src/main/assets/avatar/models` (~55 МБ). Проверено: `diff -rq avatar/models resources/models` — идентичны; `app.js:293` и `control.js:92` читают `../resources/models/...`; других ссылок на `avatar/models` в коде нет (только в аудите/шине). `resources/models` сохранён.
